# AgentDeck 首版功能清单（压缩版）

九条。界面以 `design/v3-windows.html` 与 `design/v3-phone.html` 为准，本文只记「做什么、做到哪」。

标记：● 已有　◐ 部分　○ 需新增

## 界面结构

**电脑端五页**（`v3-windows.html`，左导航）

| 页 | 放什么 |
|---|---|
| 主机 | 四项就绪度、服务与身份。只做诊断，不放任务列表 |
| 任务 | 正在执行、待批准、最近完成。只读 + 叫停，**不给批准按钮** |
| 项目 | 白名单与执行权限：配置 / 执行权限 / 日志三个标签 |
| 日志 | 任务、连接与审批的原始记录，按项目 / 任务 / 类别筛选 |
| 设置 | 接入、引擎、配对、诊断 |

**手机三标签、七屏**（`v3-phone.html`）

| 标签 | 屏 |
|---|---|
| 任务 | 任务列表（含底部输入条）→ 执行轨迹 → 叫停确认（弹层） |
| 设备 | 设备列表 → 设备详情（四项就绪度展开） |
| 审批 | 审批汇总 → 审批详情 |

通知走系统通知栏，**不新增屏**：标题只写条数（`1 条待批准`），正文只有项目名与一个数字；点通知解锁后直达该条审批详情，不经过任务列表。规格见 `v3-tokens.md` 附录 B。

## 状态与身份 —— 现在能不能连上、能不能跑

| # | 功能点 | 界面 | 现状 |
|---|---|---|---|
| 1 | 就绪度 | 四项并列、逐项可重检：通道（连通 · 28ms / 重连中 · 第 3 次 / 已停止，展开看原因与上次在线）、引擎（Codex / Cursor / WorkBuddy 的状态、路径、版本）、项目（授权数 / 可用数）、配对（已配对手机数）。失败项给原因与修复入口 | ◐ 通道与延迟已有；引擎探测只在电脑端；四项未合并，失败原因不成句 |
| 2 | 身份与配对 | 计算机名、设备 ID 短码、已配对手机指纹短码；扫码配对、撤销配对 | ● 扫码配对与撤销均已做：撤销删掉信任文件，手机下次请求即被拒 |

## 任务 —— 在跑什么、卡在哪、批不批

| # | 功能点 | 界面 | 现状 |
|---|---|---|---|
| 3 | 任务队列 | 项目、提交时间、风险等级、摘要、状态；未处理置顶，已处理折叠 | ● |
| 4 | 审批 | 完整命令或提示、工作目录、影响范围、剩余有效期；「允许一次」「拒绝」。批准要求设备凭据：解锁进场后 2 分钟内不重复要求，退到后台或超时再要求 | ● 凭据确认已实现（`KeyguardManager`；未设锁屏时给警告，可选「仍然批准」）。2 分钟复用窗口为新增——否则从通知解锁进来、点批准会再弹一次 |
| 5 | 执行轨迹 | 实时事件流，消息 / 命令 / 文件 / 审批 / 结束五类着色；可暂停跟随，断线按游标补齐 | ● |
| 6 | 预览端口 | 项目预置常用端口（默认 5173），手机一键打开电脑上的 dev server；轨迹里的 localhost 链接可直接点开；走端口隧道，不占屏幕串流 | ○ 需新增：Relay 端口隧道 + 按项目存端口 |
| 7 | 提交、续话与叫停 | 提示词提交（幂等 requestId，可重试）；结束后在同一会话上接着说；二次确认后取消 | ● |

| # | 功能点 | 界面 | 现状 |
|---|---|---|---|
| 8 | 项目白名单与执行权限 | 目录、启用状态、只读 / 可写；每项目的执行权限：访问范围（项目目录可写 / 只读）× 命令审批（按需 / 自动），并标明该策略对哪个引擎生效；越界与联接被拒的原因回显 | ● 目录、启用、只读 / 可写（默认只读，缺字段按只读处理），越界与联接被拒的原因回显；○ 命令审批策略为新增，按项目保存并传入启动参数（现为写死的 `on-request`） |
| 9 | 常驻、自启与通知 | 电脑：开机自启（服务模式，登录前即可连）；服务安装 / 卸载与 SCM 状态；关窗与退出托盘后仍接收指令，有任务在跑时退出先确认。手机：前台服务常驻 + 三条通知渠道（待批准 / 失败 / 完成） | ◐ 电脑端：服务可装可卸、状态按 SCM 显示；「重启停在登录界面仍能上线」待实机验收。○ 手机端没有后台执行体：轮询跟 Activity 前台生命周期（2–3 秒），`AndroidManifest` 只有 `INTERNET`，息屏即停；前台服务、`POST_NOTIFICATIONS`、通知渠道均为新增 |

## 两端分工

| 能力 | 手机 | Windows |
|---|---|---|
| 状态 | 只读：四项就绪度、哪台机器 | 配置、配对、撤销 |
| 任务 | 主入口：审批、叫停、提交、看轨迹、点预览 | 只读 + 叫停，**不做批准** |
| 项目 | 只读：白名单与当前策略（在审批详情里） | 全部，含执行权限 |
| 日志 | 轨迹按任务看 | 按项目 / 任务 / 类别筛选 |
| 设置 | 无（继承电脑端配置） | 全部 |
| 通知 | 系统通知栏：待批准 / 失败 / 完成，不显示命令原文 | 不发通知 |

## 判定标准

1. 手机锁屏收到通知（只显示条数与项目）→ 解锁 → 直达该条审批 → 看到命令 → 批准 → 任务继续。全程不碰电脑，也不经过任务列表。
2. 断网后恢复，事件流从断点续上，不重复不丢。
3. 手机丢失，电脑端撤销配对后立即断连。
4. 任务只能在白名单目录内工作，越界写入被拒绝并上报。
5. 一轮结束后接着说，模型记得上一轮；会话确实续不上要明确提示，不许悄悄开新会话。
6. 手机点开预览端口，看到的就是电脑上刚跑起来的那一页；刷新即最新，不占用屏幕串流。

## 砍掉

内置代理与分流规则（网络交回用户环境，不内置）、**全盘访问**（只允许项目目录，`danger-full-access` 一律不接受）、**锁屏直接批准**（通知只提示条数与项目，批准必须先解锁，不在通知上放批准按钮）、**导出日志**、留存策略、批量批准、Windows 批准入口、Windows 通知、已处理归档、Windows 多设备视图、日志保留配置、证书到期提醒、深浅主题切换（跟随系统）。
