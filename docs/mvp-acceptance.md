# 首版范围与验收

## 里程碑

首个可用版交付一个可安装的 Android APK、Windows 客户端和部署在阿里云 Linux 的 Relay。用一部手机同时管理两台电脑，在各自本机授权的测试项目里运行 Codex，查看输出、批准或拒绝操作，并在网络恢复后继续管理。

首版交互为 Codex 会话输入、输出和取消。通用 PTY、锁屏即时审批提醒、已有桌面会话接管属于后续范围。Cursor 与 WorkBuddy 保留在项目计划中，按各自的接入条件验收。

## 原型验证顺序

| 顺序 | 验证 | 通过条件 |
| --- | --- | --- |
| 1 | 手机移动数据和两台 Windows 电脑分别连接阿里云 Relay | 三端能从实际使用网络连到 `443/TCP`。转发通道中的端到端握手由手机与目标 Agent 完成，换成未配对的主机身份时连接失败 |
| 2 | Windows 重启，停在登录界面 | 服务账户能读取持久设备身份、打开项目并启动 Codex App Server。记录服务上线与 Codex 就绪两个时间点。若凭据或工具依赖交互登录，记录原因并验证可行的服务账户配置 |
| 3 | 用两个测试项目验证文件和命令边界 | 仅授权项目 A。验证正常的项目内任务可执行，访问项目 B、其他本机目录或经目录联接指向 B 的操作被拒绝。分别验证只读和可写配置，记录适配器实际能力 |
| 4 | WorkBuddy 双机定向 | 同一账号在两台测试电脑上，用无副作用的测试任务确认实际执行目标及授权范围。只在能稳定指定设备和项目时开放相应远程操作 |

原型先使用临时测试项目和测试身份。Codex 闭环优先依赖前三项，WorkBuddy 验证结果独立记录。

## 双机验收清单

测试设备记为 A、B，各自配置一个有辨识度的测试项目。手机从移动数据开始，任务使用可重复执行、容易观察的测试操作。记录构建版本、测试设备、操作结果和必要的脱敏日志。

- [ ] **安装与配对。** 在两台 Windows 电脑安装客户端，在 Android 手机上侧载 APK。两台分别本地确认配对。未确认、过期、已经使用的配对码均无法完成配对。
- [ ] **电脑端界面。** 托盘能打开设置和日志。添加、重命名、停用项目后，手机列表按设备更新。退出托盘时后台服务继续保持连接。
- [ ] **任务与审批。** A、B 各运行一个任务。A 的审批显示 A 的电脑、项目与操作。切到 B 查看输出，再回 A 批准一次。另发一个审批并拒绝，核实被拒绝的操作未执行。
- [ ] **项目边界。** 对未授权项目、已停用项目、错配的项目与会话、任意工作目录请求执行拒绝测试。在项目内构造指向另一个测试目录的目录联接，验证越界操作被拒绝。工具的文件操作与命令操作分别验证。
- [ ] **手机断线。** 在任务运行时切换 Wi-Fi 和移动数据。回到 APK 后，A 和 B 分别补齐事件。模拟提交确认丢失，用原请求 ID 查询或重试，Agent 只启动一次任务。
- [ ] **Relay 重启。** 重启 Relay，观察两个 Agent 重新连入和 APK 状态恢复。重启期间由本机 Agent 管理已启动的任务，连通后补齐事件。
- [ ] **Windows 重启。** A 停在登录界面，原设备身份自动上线。旧运行标为已中断，旧审批不可用，Codex 就绪后可继续已有会话。B 的运行不受影响。
- [ ] **撤销与日志。** 停用 A 的项目，核实正在运行的远程任务收到取消且工具进程退出，旧审批和手机日志入口失效。本机日志保留操作记录。随后撤销手机在 A 上的配对，验证已有连接被关闭，重连需重新授权。
- [ ] **日志与隐私。** 本机可按项目或任务检索日志，审计能关联任务和审批。用测试凭据确认日志不会保存凭据。Relay 不保存任务、审批和输出明文。
- [ ] **可操作性。** 手机在大字号下可读完审批详情并完成确认，状态同时用文字和图标表示。Windows 设置窗口可用键盘完成项目新增、停用和日志筛选。

首轮双机测试通过后，把真实命令、样例项目和结果收集方式固化到联调 Skill。
