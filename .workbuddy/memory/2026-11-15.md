### 对现有 UI 的诊断（windows/AgentDeck.Tray）
1. 版面失衡：1120×720 窗口内容只占顶部 ~290px，下半 60% 空白
2. 字号只有两极：Heading 25pt Bold + Body 10pt，缺中间层级

4. 主按钮浅蓝 #A5CCFF 满填充直角，视觉重量压过标题

### 迭代 2（用户反馈后重做）
用户明确指出：`ui-directions.html` 的 ABC **是同一套骨架换配色**，不算三个方向。判断正确。

教训（重要，后续别再犯）：
- 三个"方向"共用同一模板（左栏+顶栏+标题+双卡片+状态瓦片+步骤列表），只改色值/圆角/字号 → 这只是 theme variants
- 且选错了演示页面：`连接` 是配置页，任何设计体系都画成"标题+两卡"，天生无法体现结构差异

新交付 `design/ui-concepts.html`，三个概念在导航模型/主对象/密度/交互范式上完全不同，不共用骨架：
1. 收件箱：图标栏 + 列表 + 详情三栏主从，键盘流 A/D，参照 Linear inbox
2. 控制台：顶部设备 tab 带 + 左队列表格 + 右实时日志，面板分割无圆角，参照 k9s/Grafana
3. 单任务：无侧栏，居中大卡片，一次一项序列推进，超大操作区，参照安装向导

### 迭代 4：产品定位校正（关键）
用户指出根本矛盾：产品卖点是「人不在电脑前」，但首版要求「必须在 Windows 本机点批准」——自相矛盾，把产品锁死成「坐在电脑旁遥控电脑」。

结论（已与用户对齐）：
- **审批主入口改到手机端**：指纹/锁屏解锁后签发一次性短效授权（默认 5 分钟 TTL，用掉即废）
- Windows 本机批准降级为可选快捷方式，非必经环节
- 真正的安全边界是「项目白名单 + 只读沙箱 + 路径校验」，不是本地点击
- **必须改代码**：`internal/codexprobe/task.go` 现在对 Codex 工具请求调用 `declineApproval`（自动拒绝），要改成「挂起并等待手机批准」，否则远程任务永远卡在第一步
- `internal/approvals/pending.go` 已实现六元组 + 过期 + 一次性，但全项目无 import，需接入
