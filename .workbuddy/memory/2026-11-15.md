### 环境坑（重要）

### 教训（第二次踩同一个坑）
**每一稿都出现"内容只占上半屏、下半屏全空"**。原因是容器定高 720/844、内容按自然高度堆叠，没有元素吸收剩余空间。
这次有效的三种修法：
- 让最后一个信息块 `margin-top: auto` 吸底，或在容器里加一块真正有用的内容（图例 / 规则说明 / 影响范围 / 历史提示）
- 列表类允许 `overflow: hidden` 时必须先算总高，否则会**把最后一张卡片切成一半**（`pt` 六卡就踩了，减到五卡 + "上滑查看"提示）
- 手机端底部按钮要贴底：给上方可变区块 `flex: 1`，不要给按钮 `margin-top: auto`（否则空隙跑到内容中间）

## 按新 UI + 压缩清单改造代码（提交 857d3cb）

用户验收 UI 后要求按三页八条裁剪代码，点名"代码行为是自动拒绝"与需求矛盾。改动 15 文件 +816/−555。

**核心模型反转**：审批不再是"本机门禁 + 自动拒绝"，而是「Agent 把 Approv 请求降维后推给手机，阻塞等待决定」。
- `internal/codexprobe/approval.go` 重写：删掉不存在的 `availableDecisions`（真实 schema 无此字段，`command` 是字符串不是数组）与 `declineApproval`；`Approval` 只保留 Kind/ThreadID/TurnID/ItemID/Command/Cwd/Reason/GrantRoot；`NeedsDecision()` 对 `item/permissions/requestApproval`（会话级目录/网络授权）返回 false → 直接回 `{"permissions":{}}`，不打扰手机。
- `internal/codexprobe/task.go`：`RunReadOnlyTask` 增 `decide Decider` 参数；`serveApproval` 先 emit `approval/requested` 再阻塞等决定再 emit approved/declined。

- `internal/approvals/pending.go`：`Open` 不再要求 PeerID 非空（未绑定指纹的审批任何已认证手机可决定）；`Decide` 按审批 ID + 提交方指纹双校验；加 `List()`/`Close(id)`，删 `CloseRun(scope)`。
- 新增 `cmd/agentdeck-lab/task_queue.go`（agentRuntime：单线程消费队列、待批表、5 分钟审批超时）+ `task_approval.go`（`queue`/`approvals`/`approve`）+ `task_approval_test.go`。
