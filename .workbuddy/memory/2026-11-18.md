## 换 Relay 证书后 PC 自动改钉（`e34cbac`）

- `enroll -replace`：地址或证书钉扎不一致时改钉，**保留设备 ID 与路由令牌**，只重写 `agent.local.json`。
  保留 ID 是关键：服务命令行与手机设备列表都写着它，换 ID 就得重装服务、重配每台手机。
- 写入必须用新的 `replaceFile`（staging + `Root.Rename`）。`publishSubmission` 用 `Root.Link`，**故意不覆盖** —— 这正是 `relay-init` 报 `file exists` 的同一个机制，别拿它改写已有配置。
- 电脑端：`pinned` / `belongs to another Relay` 两个错误走确认弹窗，确认后改钉；`pairing\` 先改名留底，**改钉失败再原样放回**。停止 Agent 放在改钉成功之后，失败时用户手上那个还在跑。
- 开机自启服务启动时读一次配置，改钉后仍用旧证书 —— 只能重启电脑生效，界面记一条而不是装作没事。
- 实测（本机真 relay）：同端口重签 → 不带 `-replace` 报 pinned、带了成功且 ID 不变；换端口 → 报 belongs to another Relay、带了成功且 `relayUrl` 被改写。配置里的证书指纹与 `relay-init` 输出逐字一致。

## 通知进需求、锁屏批准砍掉（文档定稿）

- 用户拍板：**通知要做，锁屏批准不做**。链条：人不在电脑前有两种状态，看手机时能服务、手机息屏时服务不了；而「待批准」是用户无法预知何时到来的事件，「下次主动打开 app」可能就是几十分钟。但锁屏态只证明设备在手边、不证明是机主在看，锁屏内容旁人可见，批准与付款同级，不在此完成。
- 代码事实（决定了整条链路）：`Desk.start()` 的轮询跟 Activity 前台生命周期（`approvals` 非空 2s / 否则 3s），`stop()` 即取消 —— **息屏就停**。所以缺口不是「没通知权限」，是根本没有后台执行体。
- 另一处：`MainActivity.requestAllow()` 每次点「允许一次」都 `credential.launch(createConfirmDeviceCredentialIntent)`。按「通知→解锁→直达→批准」会解锁两次。定为**解锁进场后 2 分钟复用窗口**（退后台或超时重新要），写进清单 #4。
- 用户否决「在审批详情加一行『批准需解锁后确认』」，理由正确：能进到详情说明已解锁，文案描述的是已发生的事，等于噪音。**要防「解锁后手机被旁人拿走点批准」只能靠点击那刻的凭据，页面写字不是门槛**。
- 通知规格（tokens 附录 B，无样稿、本文即口径）：三渠道（approval/failure `IMPORTANCE_HIGH`、done `LOW`）；标题只写条数、正文「项目 · 一个数字」；**不放任何可生效按钮**；锁屏 `VISIBILITY_PUBLIC`，标题与正文直接可见——我曾提议收紧成 `PRIVATE`（锁屏只留条数、项目名解锁后展开），**用户否决，确认「只显示条数与项目」**；理由记下来：防御靠「解锁前没有任何可生效动作」，不靠藏项目名，藏了通知就退化成红点。深链 `agentdeck://approval/{id}`，失效兜底落任务列表 +「该审批已处理」。
- 不发断连通知（待批准那条本来就在栏里，单独发就变 3 秒一次）；通知文字颜色 Android 不可定制，只有 `setColor` 可碰，不用 `setColorized`。
- 文档改动：清单六处（界面结构加通知说明、#4 凭据窗口、#9 改名「常驻、自启与通知」并补手机侧现状、两端分工加通知行、判定 #1、砍掉加「锁屏直接批准」与 Windows 通知）；tokens 加附录 B + §9 对应行 + 顶部「附录 B 无样稿」声明；`v3-phone.html` 删掉审批详情 dock-hint 里原有的「需要解锁确认 ·」——正是用户反对的那句残留。

## PC 界面对齐与字体（11-19 凌晨）

用户指出 exe 与 html 的差异：表头文字没垂直居中、「2 项通过」不是绿色、整体多处不居中、字体比 html 更「锋利」。

根因与修法：

- **表头不居中**：`CardHeader` 把 `AutoSize=true + Dock=None` 的标题放进 100% 高的 TLP 单元格，它默认 `Anchor=Top|Left`，于是贴在单元格顶边。改成 `Inline()`（内嵌单行 TLP，每个子控件 `Anchor=None` 居中）＋ 整组 `Anchor=Left`——**只锚 Left 时 WinForms 会自动垂直居中**，这是关键技巧。胶囊/右侧链接同样受益。
- **胶囊颜色**：原来 `Chip()` 是个 Label，`pass != 4` 就被改成灰色，且无边框、圆角 3、等宽字体。新增自绘 `PillLabel`：20px 高、圆角 5、1px 描边、11px 正文、可选 5px 圆点，四档 tone（绿/琥珀/红/中性）；「N 项通过」现在恒为绿色（设计里绿色只表示这几项的状态，缺口由琥珀承担）。
- **字体**：原来全用 `Microsoft YaHei UI`，而 html 的栈是 `-apple-system, "Segoe UI", "Microsoft YaHei"`——Chrome 在 Windows 上拉丁走 Segoe UI、中文走 YaHei。改成 `PickFamily("Segoe UI", "Microsoft YaHei UI", ...)`，GDI 字体链接会自动把中文交给雅黑。字号按 1px=0.75pt 重算：正文 13px=9.75pt、卡片标题 13px、页标题 18px=13.5pt（原来 15pt=20px 偏大）。
- **试过但回退**：`ApplicationUseCompatibleTextRendering=true`（GDI+ 文本）——并没有更柔和，反而因为 Label 和自绘胶囊用了不同测量引擎，标题和胶囊的中线错开 5px。
- **其它对齐**：状态栏 `statusService` 补 `Anchor=Left`；`ReadyRow` 的 key 改为与 value 首个行同格（原来 RowSpan 两行再 Margin 6，视觉上低 5px）；引擎页重做成五列表格（引擎/版本/路径/能力），空列会被 TLP 丢掉导致表头整体左移 14px——补一个占位 Panel；设置页四个 pane 的卡片不再 `fill: true` 拉满（会留一大块空白），诊断页的提示行原来被 fill 占位挤到卡片底部。
